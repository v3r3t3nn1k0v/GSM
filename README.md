# GSM — бот-воронка для рынка ГСМ

Telegram-бот воронки: приветствие → анкета (5 вопросов) → заявка менеджерам в ЛС.
Брошенные заявки получают напоминание через celery-воркер, все события пишутся в журнал.

## Стек

Python 3.12, aiogram 3, SQLAlchemy 2 (async + asyncpg), Alembic, Celery + Redis, pydantic v2, docker-compose.

## Запуск

```bash
cp .env.example .env   # заполнить BOT_TOKEN, ADMIN_IDS, MANAGER_IDS
docker compose up --build
```

Поднимаются 5 сервисов: `db` (PostgreSQL 16), `redis`, `bot` (long polling, применяет миграции при старте), `worker` (celery), `beat` (расписание напоминаний каждые 10 минут).

## Переменные окружения

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `TG_PROXY_URL` | прокси для доступа к Telegram API (`socks5://user:pass@host:port`, `socks4://`, `http(s)://`); пусто — напрямую. Нужен, если VPS не может обращаться к `api.telegram.org` |
| `DATABASE_URL` | `postgresql+asyncpg://gsm:gsm@db:5432/gsm` (в docker) |
| `REDIS_URL` | `redis://redis:6379/0` (в docker) |
| `ADMIN_IDS` | ID администраторов (= менеджеров) через запятую: доступ к `/admin`, приём заявок, кнопка «Обработана» |
| `REMINDER_DELAY_MINUTES` | через сколько минут простоя слать напоминание (60) |
| `REMINDER_MAX_COUNT` | максимум напоминаний на заявку (1) |
| `CHANNEL_URL` | ссылка на Telegram-канал для кнопки «Подписаться» (пустая — кнопки не будет) |
| `TELEGRAM_CHANNEL_ID` | ID канала (вида `-100…`) для проверки подписки: без неё пользователь получает только просьбу подписаться. Бот должен быть админом канала. Пусто — проверка выключена |
| `AVITO_CLIENT_ID` / `AVITO_CLIENT_SECRET` | ключи приложения с developers.avito.ru (Messenger API). Пусто — интеграция с Авито выключена |
| `AVITO_USER_ID` | номер профиля Авито (из ссылки на профиль) |
| `GROQ_API_KEY` | ключ Groq (console.groq.com): AI-ассистент живыми ответами общается с клиентами Авито. Пусто — шаблонные автоответы |
| `GROQ_MODEL` | модель Groq (по умолчанию `openai/gpt-oss-120b`; список актуальных — `GET https://api.groq.com/openai/v1/models`) |
| `GROQ_PROXY_URL` | прокси для api.groq.com, если он недоступен с VPS (формат как `TG_PROXY_URL`) |

## VPS не видит Telegram: `TelegramNetworkError: Request timeout error`

Первый запрос бота — `get_me()` к `api.telegram.org`. Таймаут на нём означает,
что сервер не может обратиться к Telegram напрямую (частая ситуация на хостингах
в РФ — они блокируют Telegram API). Приложение при этом не падает, а ждёт связи
и повторяет попытку каждые 15 секунд; чтобы бот заработал, поднимите прокси
и укажите его в `TG_PROXY_URL`.

Вариант без покупки прокси — SOCKS5-туннель по SSH до любой машины,
где Telegram доступен. Чтобы туннель не зависел от открытого окна SSH и
переживал перезагрузки, оформите его systemd-сервисом на VPS.
Сначала вход на зарубежную машину по ключу (без пароля):

```bash
ssh-keygen -t ed25519
ssh-copy-id user@foreign-server
```

Затем `/etc/systemd/system/ssh-tunnel.service`:

```ini
[Unit]
Description=SSH SOCKS-туннель для доступа к Telegram API
After=network-online.target
Wants=network-online.target

[Service]
ExecStart=/usr/bin/ssh -N -D 172.17.0.1:1080 \
    -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
    -o ExitOnForwardFailure=yes -o StrictHostKeyChecking=accept-new \
    user@foreign-server
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now ssh-tunnel
ss -tlnp | grep 1080   # должно быть LISTEN на 172.17.0.1:1080
```

и в `.env` (адрес `172.17.0.1` — это сам VPS, каким его видят контейнеры):

```
TG_PROXY_URL=socks5://172.17.0.1:1080
```

Если в логах бота `Couldn't connect to proxy 172.17.0.1:1080 [Errno 111]` —
на VPS ничего не слушает порт 1080: туннель не запущен (`systemctl status
ssh-tunnel`) или ssh запущен без адреса привязки (слушает только 127.0.0.1,
контейнеры его не видят — нужен именно `-D 172.17.0.1:1080`). Бот при этом
не умирает, а повторяет попытку каждые 15 секунд.

Подойдёт и любой внешний/платный прокси в формате
`socks5://user:pass@host:port` или `http://host:port`. После правки `.env`:
`docker compose up -d --force-recreate bot worker`.

## Логика

- **Проверка подписки** (если задан `TELEGRAM_CHANNEL_ID`) — на каждое сообщение и нажатие кнопки бот проверяет `get_chat_member`: неподписанный вместо ответов получает сообщение с кнопками «📢 Подписаться» и «✅ Я подписался»; после подписки доступ открывается (нажать кнопку и `/start`). Админы из `ADMIN_IDS` проверку не проходят. Если API не отвечает, пользователь пропускается — сбой не блокирует бота.
- **/start — вопрос о цели** — «Вы будете использовать топливо для личных целей?» с кнопками «✅ Да» / «❌ Нет».
- **Да (потребитель, `users.status = consumer`, дефолт)** — обычная анкета: вид топлива (кнопки АИ/ДТ), сети АЗС, объём/мес, регион, доставка, ФИО (свободный текст), телефон (текстом или кнопкой «Поделиться контактом»). Заявка создаётся при первом шаге со статусом `partly_filled`, при завершении — `filled` и рассылка админам-менеджерам. Повторный выбор роли продолжает открытую заявку с места остановки.
- **Нет → оффер агента** — «Да» → анкета из одного вопроса (телефон, текстом или контактом), статус `agent`, телефон в `users.phone`, уведомление админам «Новый агент»; «Нет» → обещание новостей + кнопка канала (`CHANNEL_URL`).
- **Админ = менеджер**: один список `ADMIN_IDS` — им доступна `/admin` и им приходят заявки с inline-кнопкой «✅ Заявка обработана». Нажатие переводит заявку в `processed` (пишется в журнал) и убирает её из списка новых.
- **Напоминания** — beat каждые 10 минут; заявкам `partly_filled` без активности дольше `REMINDER_DELAY_MINUTES` и с `reminders_sent < REMINDER_MAX_COUNT` отправляется сообщение. Отправка фиксируется в `logs` (`reminder_sent`).
- **Админка** `/admin` — статистика, заявки с вкладками «Новые / Обработанные / Все» и пагинацией, рассылка с выбором аудитории: потребителям / агентам / всем (заблокировавшие бот пропускаются через try/except).
- **Статусы заявки**: `partly_filled` → `filled` (ждёт обработки) → `processed`.
- **Статусы пользователя**: `consumer` (потребитель, дефолт) / `agent` (агент).
- **Журнал `logs`** — события `new_user`, `new_application`, `reminder_sent`, `application_processed`, `agent_registered`.
- **Интеграция с Авито** (если заданы `AVITO_*`) — celery beat каждые 30 секунд опрашивает чаты по объявлениям (официальное Messenger API). Первый контакт создаёт «тихую» заявку (`source='avito'`, `partly_filled`, без пользователя бота): AI-ассистент общается с клиентом и **извлекает данные заявки** (вид топлива, объём/мес, регион, телефон — вторым вызовом Groq + регулярка на телефон). Менеджерам заявка прилетает с кнопкой «✅ Заявка обработана» **только когда собраны все поля** (`filled`); до этого менеджеров не дёргаем. Ни одно входящее не остаётся без ответа: если последнее сообщение чата — от клиента, бот всегда отвечает (AI, а при сбое Groq — шаблоном с перечнем недостающих полей); повтор попытки, если отправка не прошла. По готовой/обработанной заявке новые сообщения клиента → «новое сообщение по заявке №X» / «клиент вернулся». Если клиент написал 10+ сообщений, а данных всё нет — эскалация менеджерам с тем, что собрано. Курсор `avito_last_message_id` даёт идемпотентность. Требования: тариф Авито «Максимальный» (товары) / «Расширенный»+ (услуги), ключи приложения.
- **AI-ассистент на Groq** (если задан `GROQ_API_KEY`) — вместо шаблона клиентам Авито отвечает LLM: контекстные ответы по переписке (вид топлива, объём, регион, телефон), жёсткий промпт «не называть цены и не выдумывать факты». Предохранители: не чаще 1 ответа в 2 минуты, максимум 15 ответов на чат, молчит по обработанным заявкам и сразу после ответа менеджера; любой сбой Groq → шаблонный автоответ/тишина, лид не теряется. Уведомление менеджеру помечено «🤖 AI-ассистент ответил: …».

Проверить напоминания вручную, не дожидаясь beat:

```bash
docker compose run --rm worker celery -A app.reminders.celery_app.celery_app call reminders.send_pending
```

## Структура

```
bot/            слой Telegram: users / agent / application / admin
                (в каждом handlers, routers, keyboards, texts [+ states])
app/            бизнес-логика: users / applications / logs / reminders
                (models, schemas, repository, service)
alembic/        миграции (URL берётся из .env)
```
