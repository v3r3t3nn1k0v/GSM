# План: Telegram-бот-воронка для рынка ГСМ

## Контекст
Проект с нуля (репозиторий пуст). Бот-воронка: приветствие автора канала → анкета из 5 вопросов → заявка менеджерам в ЛС (MANAGER_IDS из .env). Незаполненные заявки (статус `partly_filled`) через celery-воркер получают напоминание (через 1 час простоя, максимум 1 на заявку). Админка для ADMIN_IDS: статистика, последние заявки, рассылка. Всё логируется в таблицу logs.

## Стек
Python 3.12, aiogram 3.x, SQLAlchemy 2.0 (async + asyncpg), Alembic, Celery + Redis (брокер + FSM storage + beat), pydantic v2 / pydantic-settings, docker-compose.

## Модели (SQLAlchemy → pydantic-схемы)

**users**: id PK, telegram_id BigInteger unique, username str|None, nickname str, premium bool, created_at, updated_at. *(поле `updatet_at` из ТЗ пишу как `updated_at`)*

**applications**: id PK, user_id FK→users, status Enum(`partly_filled`, `filled`), fuel_type str|None (АИ/ДТ), gas_networks text|None, monthly_volume text|None, region text|None, delivery_needed text|None, reminders_sent int=0, last_reminder_at datetime|None, created_at, updated_at.

**logs**: id PK, event Enum(`new_user`, `new_application`, `reminder_sent`), user_id FK|None, application_id FK|None, payload JSON|None, created_at.

## Сценарии

**1. /start** (bot/users): upsert юзера по telegram_id → лог `new_user` → приветственный текст (дословно из ТЗ) + inline-клавиатура с одной кнопкой **«📝 Заполнить анкету»**.

**2. Анкета** (bot/application, FSM): кнопка → создание заявки `partly_filled` + лог `new_application` → вопросы по очереди:
- «Какой вид топлива вас интересует?» — inline: АИ / ДТ
- «Какими сетями АЗС Вы предпочитаете пользоваться?» — текст
- «Какой ориентировочный объём топлива необходим в месяц?» — текст
- «В каком регионе планируете заправляться?» — текст
- «🚛 Нужна ли доставка топлива на Ваши объекты?» — текст

Каждый ответ обновляет заявку (updated_at = момент активности — от него считается «простой»). После последнего ответа: статус `filled`, форматированная заявка → в ЛС каждому MANAGER_IDS, подтверждение пользователю.

**3. Напоминания** (app/reminders): beat каждые 10 минут → задача ищет `partly_filled` с `updated_at < now−60мин` и `reminders_sent < 1` → шлёт сообщение через собственный инстанс Bot в воркере → `reminders_sent += 1`, лог `reminder_sent`. Ошибки Telegram (заблокировал бота) глушатся с записью в payload.

**4. Админка** (bot/admin, фильтр IsAdmin): /admin → inline-меню «📊 Статистика» / «📋 Последние заявки» / «📢 Рассылка». Статистика: всего юзеров, новых за сегодня, заявки по статусам. Заявки: последние 10 с деталями. Рассылка: FSM-ввод текста → подтверждение → отправка всем юзерам.

## Ключевые решения
- FSM-хранилище — Redis (сессии переживают рестарт контейнера).
- Бот при старте применяет миграции (`alembic upgrade head`) перед polling.
- Repository — только запросы; service — транзакционная логика + логирование; handlers тонкие.
- Enum-статусы и события — питоновские enum + SA Enum(native_string=False) для простоты миграций.

## Порядок работ

2. Модели + схемы + миграция Alembic
3. app-слой: repositories, services, celery

5. Сквозная проверка

## Проверка
- `docker compose up --build` — все 5 сервисов поднимаются, миграция применяется.
- Э2Е в Telegram: /start → юзер в БД; пройти анкету → заявка `filled`, менеджер получил сообщение.
- Частичное заполнение → заявка `partly_filled`; вручную дернуть задачу `docker compose run --rm worker celery -A app.reminders.celery_app call tasks.send_reminders` → напоминание пришло, в logs запись `reminder_sent`, повторно не шлётся.
- /admin от ADMIN_ID: статистика сходится с БД; рассылка доходит.
- Негативный кейс: /admin от не-админа — нет доступа.
